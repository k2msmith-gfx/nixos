The user's Doom config is nix-managed. `~/.config/doom/config.el` (and init.el/packages.el) are **symlinks into the nix store** (`/nix/store/…-home-manager-files/.config/doom/…`), generated by home-manager from the source at `~/nixos/doom/`.

Consequence: editing `~/nixos/doom/config.el` does **not** affect a running/relaunched Emacs — it still loads the pre-existing store copy, silently (no error, the new code just isn't there). To activate a Doom-config change:

```
darwin-rebuild switch --flake ~/nixos#kevmac
```

(nix-darwin flake, config name `kevmac`, macOS host "Mac-mini"; needs sudo) then restart Emacs.

Exception: files that config.el `load`s by **absolute live path** are NOT nix-managed and take effect on Emacs restart alone. E.g. `~/devel/ray/emacs/janet-live-mode.el` is loaded directly from the ray repo — editing it needs only an Emacs restart / `load-file`, no rebuild. So a change spanning Doom config + ray elisp needs a rebuild only for the Doom-config half.

Discovered 2026-07-29 adding the right-click context menu: `(context-menu-mode 1)` in ~/nixos/doom/config.el appeared to do nothing until the rebuild. See [[reference_repo_paths]], [[reference_doom_janet_lsp_routing]].
